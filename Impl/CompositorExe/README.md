# Compositor

A graphical editor for ACF (Application Component Framework) component registries.

## Overview

Compositor is a cross-platform desktop application built on top of the
[ACF Framework](https://github.com/ImagingTools/Acf). It provides a visual, diagram-based
interface for creating, editing, and previewing ACF registry files (`.arx`, `.alx`) without
the need to edit raw XML.

A registry file describes a composition of ACF components – their configuration, attributes,
and how they reference each other. Compositor renders this composition as an interactive
node-and-connector diagram and provides specialized panels for all editing tasks.

## Features

| Feature | Description |
|---------|-------------|
| **Visual diagram editor** | Components as nodes, references as connector lines with drag-and-drop support |
| **Attribute editor** | Type-safe editing of all component attributes with undo/redo |
| **Package browser** | Filterable tree of all available ACF packages and their components |
| **Quick help** | Inline HTML documentation for the selected component |
| **User notes** | Free-text annotations per component, saved with the registry |
| **Registry consistency check** | Automatic validation of references, types, and attribute values |
| **Registry preview** | Execute the current registry in an isolated context without leaving the editor |
| **XPC editor** | Edit eXtended Pixel Configuration models |
| **Multi-document interface** | Multiple registries open simultaneously with dockable panels |
| **Undo / Redo** | Full undo/redo stack per document |
| **Internationalization** | 8 languages supported |
| **Cross-platform** | Windows, macOS, and Linux via Qt 5 / Qt 6 |

## Architecture

Compositor follows ACF's layered component architecture:

```
CompositorExe          Executable entry point (main.cpp)
      │
      ▼
CompositorVoce         Application definition (Partitura/*.acc files)
      │                Declares the full component tree of the application
      ▼
CompositorPck          Component package (shared library)
      │                Exports ~15 editor components
      ▼
icmpstr                Implementation library
      │                ~20 classes: visual registry model, Qt graphics, editors
      ▼
ACF Framework          icomp, ipackage, ibase, idoc, iqtgui, imod, iser, …
```

The ACF principle *"a composition of components is itself a component"* means the
entire Compositor application is a single root component (`CCompositor`) that recursively
owns all sub-components. The root component is generated by the ACF compiler (`arxc`) from
`Compositor.acc`.

## Application Definition (Partitura)

The `Partitura/CompositorVoce.arp/` directory contains the declarative application
structure as ACF `.acc` XML files. Each file configures a logical part of the application:

| File | Purpose |
|------|---------|
| `CompositorApplication.acc` | General application properties, settings dialog binding, version info |
| `CompositorTemplate.acc` | Document template: registry file format, undo manager, view binding |
| `CompositorDockWidgets.acc` | Container and layout of all dockable panels |
| `CompositorSettings.acc` | Persistent application settings (paths, display options) |
| `CompositorSettingsDialog.acc` | Qt dialog for editing application settings |
| `VisualRegistry.acc` | Visual registry data model (ACF registry + 2D layout metadata) |
| `VisualRegistryView.acc` | Qt graphics scene configuration for the diagram editor |
| `AttributeEditorDock.acc` | Dockable attribute editor panel |
| `PackageOverviewDock.acc` | Dockable package and component browser |
| `ClassHelpDock.acc` | Dockable quick-help panel (HTML documentation viewer) |
| `ComponentNoteEditorDock.acc` | Dockable user-notes editor panel |
| `RegistryOverviewDialog.acc` | Tree-view dialog for hierarchical registry overview |
| `SelectableConfigData.acc` | Selectable package configuration profiles |
| `XpcTemplate.acc` | Document template for XPC model files |
| `CompositorTranslationManager.acc` | Runtime language loading |

## Key Components

### Data Model

**`CVisualRegistry`** (`Include/icmpstr/CVisualRegistry.h`)  
The central document model. Extends `icomp::CRegistry` with 2D layout information
(position and size of each node), user notes per component, and full XML serialization.
Notifies observers via ACF's `istd::IChangeable` mechanism.

**`CVisualRegistryElement`** (`Include/icmpstr/CVisualRegistryElement.h`)  
Represents a single component entry in the visual registry, holding its 2D position,
visual properties, and any user-attached note.

### Visual Editor

**`CVisualRegistryEditorComp`** (`Include/icmpstr/CVisualRegistryEditorComp.h`)  
The main editor widget. A `QGraphicsView`-based component that renders the registry as a
diagram, handles drag-and-drop from the package browser, multi-selection, zoom/pan,
snap-to-grid, context menus, and observes `CVisualRegistry` for model changes.

**`CRegistryElementShape`** (`Include/icmpstr/CRegistryElementShape.h`)  
A `QGraphicsItem` rendering one component as a colored rectangle with name, class label,
and reference ports.

**`CGraphicsConnectorItem`** (`Include/icmpstr/CGraphicsConnectorItem.h`)  
A `QGraphicsItem` rendering a directed connection (reference) between two components.

### Editor Panels

**`CAttributeEditorComp`** – Observes selection; builds a type-safe form for all
attributes of the selected component. Delegates complex multi-value attributes to
`CMultiAttributeEditor`.

**`CPackageOverviewComp`** – Filterable tree of all packages and components; acts as
drag-and-drop source for the diagram editor.

**`CQuickHelpGuiComp`** – Renders HTML component documentation from
`.arp.info/` directories.

**`CComponentNoteEditorComp`** – Free-text note editor per component.

**`CRegistryTreeViewComp`** – Hierarchical tree view of the registry, complementing the
diagram view.

**`CXpcEditorComp`** – Form-based editor for XPC (eXtended Pixel Configuration) models.

### Services

**`CRegistryLoaderComp`** – Reads and writes `.arx` (registry XML) and `.alx`
(registry + layout XML) files.

**`CRegistryPreviewComp`** – Executes the current registry in an isolated ACF context
for live preview.

**`CRegistryConsistInfoComp`** – Validates registry consistency: missing references,
type mismatches, duplicate IDs.

**`CPackagesLoaderExtComp`** – Extends `ipackage::CPackagesLoaderComp` with meta-info
caching; provides paths to HTML descriptions and SVG images for each component.

## Building

### Prerequisites

- **ACF Framework** – set `ACFDIR` environment variable to the ACF root directory, or
  place the `Acf` repository as a sibling of `AcfSln`
- **Qt 5.15** or **Qt 6.x** (Core, Widgets, GUI, Xml, PrintSupport, Svg)
- **CMake 3.15+** or **qmake** (legacy)
- **C++11** compatible compiler (MSVC, GCC, Clang)

### CMake

```bash
# From the repository root
cd Build/CMake
cmake -DACFDIR=/path/to/Acf .
cmake --build . --target Compositor
```

### QMake (legacy)

```bash
cd Impl/CompositorExe/QMake
qmake Compositor.pro
make          # Linux / macOS
nmake         # Windows (MSVC)
```

### Conan

The project can be consumed via the Conan package manager. The `acfsln` package
automatically pulls in the `acf` and `qt` dependencies:

```bash
conan install . --build=missing
```

## Running

```bash
# Run directly (packages are loaded from the current directory by default)
./Compositor

# Specify a custom package configuration
./Compositor --config /path/to/AcfSlnConfig.awc
```

On **Windows**, the Fusion style is applied automatically and Windows dark mode is disabled
for consistent rendering across OS versions.

On **macOS**, the application is built as an `.app` bundle using the metadata in
`Impl/CompositorExe/Mac/Info.plist` (both for CMake and QMake). A valid bundle with a
`CFBundleIdentifier` is required by AppKit services, in particular for the native file
selection panels (`NSOpenPanel` / `NSSavePanel`).

## File Formats

| Extension | Description |
|-----------|-------------|
| `.arx` | ACF Registry XML – standard ACF component composition file |
| `.alx` | ACF Layout XML – registry plus visual diagram layout metadata |
| `.acc` | ACF Component Configuration – component definition / application definition |
| `.awc` | ACF Working Configuration – package loader configuration file |
